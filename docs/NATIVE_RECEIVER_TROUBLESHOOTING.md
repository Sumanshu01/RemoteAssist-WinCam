# RemoteAssist WinCam — Native Windows 11 Receiver: Troubleshooting Guide

## 1. Environment & Build Diagnostics

### Error: `cmake` or `cl.exe` not recognized

- **Cause**: Visual Studio 2022 or CMake is either not installed or not added to your system `PATH`.
- **Resolution**:
  1. Open the **Developer Command Prompt for VS 2022** or **Developer PowerShell for VS 2022** from your Windows Start Menu.
  2. Verify compiler availability:
     ```cmd
     cl.exe
     cmake --version
     ```
  3. If compiling in standard PowerShell without the developer environment, initialize the toolset:
     ```powershell
     & "C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Auxiliary\Build\vcvars64.bat"
     ```
  4. **MinGW Fallback**: If Visual Studio 2022 is not yet installed on your development machine, the unit test suite and core pipeline can be compiled using the installed MinGW GCC compiler:
     ```cmd
     g++ -std=c++14 -I native/windows-receiver/include native/windows-receiver/src/receiver_core.cpp native/windows-receiver/src/logger.cpp native/windows-receiver/tests/test_receiver_core.cpp -o test_runner.exe
     .\test_runner.exe
     ```

## 2. Direct3D 11 & Viewport Rendering

### Issue: `D3D11CreateDeviceAndSwapChain` returns `DXGI_ERROR_UNSUPPORTED`

- **Cause**: The receiver is running inside a virtual machine (VM), Remote Desktop (RDP) session, or an environment without a hardware GPU supporting Direct3D feature level 11.0+.
- **Resolution**: The `RenderEngine` implementation in `src/render_engine.cpp` includes an automatic fallback to **WARP** (Windows Advanced Rasterization Platform):
  ```cpp
  if (FAILED(hr)) {
      // Automatic fallback to WARP software driver
      hr = D3D11CreateDeviceAndSwapChain(
          nullptr,
          D3D_DRIVER_TYPE_WARP,
          nullptr,
          0,
          featureLevels,
          2,
          D3D11_SDK_VERSION,
          &scd,
          &m_swapChain,
          &m_d3dDevice,
          &featureLevel,
          &m_d3dContext
      );
  }
  ```
  If running in CI/CD without an active display session, pass the `--headless` flag to run without window creation:
  ```cmd
  RemoteAssistWinReceiver.exe --headless --test
  ```

## 3. WebRTC Signaling & Authentication

### Error: `StatusCode::AuthenticationFailed` (-8)

- **Cause**: The session code or authentication token provided via `--token` or `--session` is missing, malformed, or expired.
- **Resolution**:
  - Verify that the signaling server is running: `curl http://localhost:4000/health`.
  - Pass a valid token and session code generated by the dashboard or signaling API:
    ```cmd
    RemoteAssistWinReceiver.exe --session=RAW-482-195 --token=raw_tok_helper_valid_2026
    ```
  - Inspect structured logs for auto-redacted diagnostic output.

## 4. Two-Party Consent & Frame Ingestion

### Issue: `pushIncomingFrame` returns `StatusCode::ConsentRequired` (-2)

- **Cause**: Frames are arriving, but active two-party consent has not been granted.
- **Architectural Guardrail**: By architectural design, video frames are **strictly dropped** and not decoded or rendered until `updateConsent(ConsentState::Granted)` is executed following mutual user agreement.
- **Resolution**:
  - In normal operation, wait for the applicant in India to click **"Grant Consent & Start Live Assist"**.
  - In self-test mode, pass the `--test` flag which executes the synthetic consent agreement sequence.

---

## 5. Windows 11 Virtual Camera Registration Diagnostics

### Error: `MFCreateVirtualCamera` returns `E_ACCESSDENIED` (0x80070005)

- **Cause**: Attempting to register with `MFVirtualCameraAccess_AllUsers` without Administrator privileges.
- **Resolution**: Change access level to `MFVirtualCameraAccess_CurrentUser` which executes in unprivileged user-mode.

### Issue: Virtual Camera not visible in Zoom / Teams

- **Cause**: Windows 11 camera permissions are disabled globally or per-app.
- **Resolution**:
  1. Open Windows 11 **Settings > Privacy & security > Camera**.
  2. Ensure **"Camera access"** is toggled **ON**.
  3. Ensure **"Let desktop apps access your camera"** is toggled **ON**.
